## Partie 2 — Audit Project2 (pourquoi les résultats sont toujours faux)

### 2.1 Racine n°1 — Bug de mélange de cibles dans le RRS 🔴

`scripts/md_calculate_rrs_acsi_pns.py` L100–118 groupe par SMILES **sans séparer les cibles** :

```python
wt_rows = grp[grp["mutation"] == "WT"]          # mélange PfDHFR-WT ET PfCRT-WT
dg_wt = wt_rows["vina_score"].mean()            # moyenne cross-cible
...
dg_mut = mut_rows["vina_score"].mean()          # chaque mutant n'a qu'UNE cible
rrs_vals[mut] = (abs(dg_mut) / abs(dg_wt)) * 100
```

**Conséquence vérifiée numériquement** (composé `C=CCc1cc(OC)c2c(c1OC)OCO2`) :
- WT moyen = −7.5 (mélange PfDHFR −7.6 et PfCRT −7.4).
- RRS_N51I = |−4.72| / 7.50 = 62.9% — mais N51I est un mutant **PfDHFR uniquement** ; le bon dénominateur est −7.6 → 62.1% par hasard proche ici, mais le principe est faux.
- `c_rrs_classification.csv` : RRS > 100% à 5/6 mutants (jusqu'à 177.5%) = artefact de dénominateur cross-cible.
- `docking_mutants.csv` : 136 lignes (17 composés × 8 états) — seuls PfDHFR et PfCRT ont des mutants dockés ; PfATP4 et PfClpP absents. Pourtant les classes A/B/C/D sont présentées comme une résilience pan-cible.

**Fix :** RRS par cible (chaque score mutant divisé par le WT de SA cible), puis agrégation documentée.

### 2.2 Racine n°2 — Mismatch force field dans TOUS les systèmes de production 🔴

- Protocole (`scripts/md_simulation_protocol.md` L7, L22-23, L96-98) : **CHARMM36m + CGenFF requis ; « Do not use GAFF2 output for production runs »**.
- Réalité : les 4 ligands (`MD_systems/*/ligand_*.itp`) sont tous **acpype/GAFF2** (header « created by acpype »), protéine CHARMM36m.
- Le manuscrit se contredit : L241 dit « ACPyPE/GAFF2 », L666 dit « CGenFF v4.4 / OpenFF 2.2 ».
- `md_prepare_ligands.log` : `antechamber: Fatal Error! Cannot properly run sqm` — GAFF2 jamais produit correctement pour tous les ligands.

### 2.3 Racine n°3 — MM-GBSA non physique 🔴
